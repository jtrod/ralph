# Ralph

Drive iterative development loops with Claude using a live TUI dashboard. Ralph spawns `claude -p` processes against a PROJECT file, displaying real-time progress in tasks, output, and cost.

See [ralph-prd.md](ralph-prd.md) for detailed documentation.

## Quick Start

1. **Install:**
   ```bash
   npm install github:jtrod/ralph
   ```

2. **Generate your PRD file** in Claude Code (this is the file ralph reads):
   ```
   /prd "describe your project here"
   ```

3. **Start the loop** against the file `/prd` produced:
   ```bash
   npx ralph example_prd.md
   ```

## Usage

```bash
npx ralph <prd-file> [iterations=10] [--budget <usd>] [--sequential]
```

**Arguments:**
- `<prd-file>` — Path to the PRD file generated by `/prd`
- `[iterations=10]` — Max iterations before giving up. Sequential mode only —
  parallel mode runs every work-group wave once and ignores this value (default: 10)
- `[--budget <usd>]` — Max USD to spend
- `[--sequential]` — Force the one-task-per-iteration loop instead of parallel waves
  (`--no-parallel` is an alias)
- `[--max-parallel <n>]` — Cap concurrent agents per wave (default: 6)

### Parallel mode (default)

By default Ralph runs the tasks in each work group (`### W1`, `### W2`, …) **at the same time**,
each in its own isolated git worktree; groups still run in order. After a group's agents finish,
Ralph merges each task's branch back to your base branch **one at a time**, runs your test suite
(`npm test` if present) after each merge, and on a conflict or test failure rolls that task back and
retries it on its own. Ralph — not the agents — records task check-offs and `PROGRESS.md` entries
after a successful merge.

Parallel mode needs a **git repository with a clean working tree** and a PRD containing `### Wn`
tasks. When any of those don't hold — not a git repo, dirty tree, or no parseable tasks — Ralph
prints a notice and **automatically falls back to the sequential loop**, so it always runs. Pass
`--sequential` to force the sequential loop explicitly.

Contract for parallel-safe PRDs:
- Tasks in the **same group must touch disjoint files** (two tasks editing the same file will
  conflict and fall back to a slow sequential retry). Put dependent or file-sharing tasks in
  **different** groups — `/prd` documents this rule and prefers wide groups of independent tasks.

## Requirements

- **Node.js** >= 18
- **Claude CLI** on your PATH ([install](https://docs.claude.com/claude-code))
- **Terminal:** Real TTY for dashboard; use `ralph.sh` for CI
